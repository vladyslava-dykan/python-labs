# Лабораторна робота №4. Перегляд запису CVE з NVD

Консольна утиліта отримує запис про вразливість за CVE-ідентифікатором (з NVD CVE API 2.0
або з локального JSON-файлу) і виводить один JSON-звіт за правилом варіанта.

## Варіант
**Варіант 8.** Напрям відбору: зміна меж впливу.

Правило: `score >= 9.0` і `cvssData["scope"] == "CHANGED"` у тій самій вибраній оцінці
CVSS v3.1. Тоді `decision = "review"`, інакше `other`.

## Встановлення залежностей
З кореня репозиторію, у віртуальному середовищі:

```
pip install -r requirements.txt
```

## Структура

```
labs/lab04/

```

## Запуск

### Локальний режим (без мережі)

```
python -m labs.lab04.main --cve CVE-2099-10001 --input labs/lab04/data/nvd_sample.json
```

`CVE-2099-10001` — штучний запис, лише для локальної перевірки. Очікується
`"decision": "other"`: оцінка 9.8 вища за поріг, але `scope` має значення `UNCHANGED`.

### Режим NVD (один запит до сервісу)

```
python -m labs.lab04.main --cve CVE-2021-44228
```

Не запускайте пакетні або циклічні запити: NVD обмежує кількість запитів (без ключа — близько
п'яти за 30 секунд). Для розроблення та перевірок використовуйте локальний режим.

### Ключ NVD (необов'язково)

Запуск без ключа працює. Якщо змінна середовища `NVD_API_KEY` непорожня, ключ передається в
заголовку `apiKey` (не в адресі запиту) і ніде не виводиться. Приклад для PowerShell:

```
$env:NVD_API_KEY = "ваш-ключ"
Remove-Item Env:NVD_API_KEY
```

Не записуйте справжній ключ у файли проєкту.

## Коди завершення

| Код | Значення |
|-----|----------|
| 0 | звіт сформовано (зокрема `not_found`, `rejected`, `insufficient_data`) |
| 1 | помилка отримання або читання даних, некоректна структура відповіді |
| 2 | неправильні аргументи командного рядка або номер варіанта |

Повідомлення про помилки виводяться в `stderr`, а JSON-звіт — лише в `stdout`.

## Формат звіту

Звіт завжди містить ключі (відсутні значення подаються як `null`):
`cve_id`, `variant`, `description`, `vuln_status`, `cvss_version`, `score`, `score_source`,
`vector`, `rule` (`threshold`, `field`, `expected`), `observed`, `decision`.

Значення `decision`:

- `not_found` — запису з таким CVE немає;
- `rejected` — запис відхилено (`vulnStatus = Rejected`);
- `insufficient_data` — немає статусу, оцінки CVSS v3.1 або поля, потрібного для варіанта;
- `review` — виконано правило варіанта;
- `other` — правило не виконано.

Брак даних не означає відсутності небезпеки.
